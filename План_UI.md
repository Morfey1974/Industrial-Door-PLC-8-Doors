## 5. ТЕХНИЧЕСКАЯ АРХИТЕКТУРА

### 5.1 Выбранный стек: React

**Решение:** Использовать React, так как:
- Проект будет сложным (логика дверей, взаимосвязи, карта)
- Нужны мощные инструменты для разработки
- Web-интерфейс НЕ встраивается в прошивку (отдельное приложение)
- В прошивку пойдет только конфигурация (данные), а не сам интерфейс

**Преимущества React для этого проекта:**
1. **Компонентный подход** — легко создавать переиспользуемые компоненты (кнопки, таблицы, карточки дверей)
2. **Реактивность** — автоматическое обновление UI при изменении данных из API
3. **Управление состоянием** — Context API и хуки для глобального состояния (аутентификация, настройки)
4. **Роутинг** — React Router для навигации между страницами (SPA)
5. **Хуки** — кастомные хуки для API запросов, автообновления, аутентификации
6. **Экосистема** — множество библиотек для форм, графиков, таблиц
7. **Инструменты разработки** — React DevTools, горячая перезагрузка (HMR)
8. **Масштабируемость** — легко добавлять новые функции (карта, логика дверей, взаимосвязи)
9. **Производительность** — виртуальный DOM, оптимизация рендеринга
10. **Поддержка** — большое сообщество, много ресурсов и примеров

### 5.3 Технологии

**Основной стек:**
- **React 18+** — UI библиотека
- **React Router** — маршрутизация (SPA)
- **Vite** — сборщик и dev-сервер (быстрый, современный)
- **CSS Modules** или **Styled Components** (опционально) — стилизация

**Дополнительные библиотеки (по необходимости):**
- **Axios** или **Fetch API** — HTTP запросы
- **React Query** или **SWR** — управление состоянием сервера, кэширование
- **React Hook Form** — управление формами
- **Date-fns** — работа с датами/временем
- **Recharts** или **Chart.js** — графики для статистики (если понадобится)

**Инструменты разработки:**
- **ESLint** — линтинг кода
- **Prettier** — форматирование кода
- **TypeScript** (опционально) — типизация (можно добавить позже)

### 5.4 Размещение в проекте

- **Папка:** `WebUI/` в корне workspace STM32CubeIDE
- **Разработка:** 
  - Visual Studio Code (рекомендуется для React)
  - Или Visual Studio (с поддержкой Node.js проектов)
- **Запуск:** Отдельное приложение, работает независимо от прошивки
- **Деплой:** 
  - Статический хостинг (nginx, Apache)
  - Или отдельный веб-сервер
  - Или встроенный веб-сервер на контроллере (если понадобится позже)

### 5.5 Взаимодействие с контроллером

- **API Endpoint:** `http://<IP_контроллера>:<port>/api/*`
- **CORS:** Контроллер уже поддерживает CORS (`Access-Control-Allow-Origin: *`)
- **Протокол:** HTTP/1.1, JSON
- **Аутентификация:** Будет добавлена в этапе 9.5 (сессии, токены)

### 5.6 Конфигурация дверей

**Важно:** В прошивку пойдет только **конфигурация** (данные):
- Логика работы дверей
- Взаимосвязи между дверьми
- Параметры (таймауты, правила)
- НЕ сам Web-интерфейс

**Формат передачи:**
- Web UI → `PUT /api/config` → Контроллер → Сохранение в QSPI Flash

### Этап 3: API интеграция и хуки
**Цель:** Подключение к существующим API endpoints через React

**Задачи:**
1. Создать `services/api.js` с функциями для всех endpoints:
   - `getState()` → `GET /api/state`
   - `getDoors()` → `GET /api/doors`
   - `getConfig()` → `GET /api/config`
   - `putConfig(data)` → `PUT /api/config`
   - `getJournalStat()` → `GET /api/journal/stat`
   - `getJournalDump(offset, limit)` → `GET /api/journal/dump`
2. Создать кастомный хук `useApi.js` для работы с API:
   - Состояние загрузки (loading)
   - Обработка ошибок
   - Кэширование (опционально)
3. Создать хук `useAutoRefresh.js` для автообновления данных
4. Настроить базовый URL контроллера (конфигурация)
5. Обработка ошибок сети и таймауты

**Результат:** Готовый модуль API и хуки для работы с контроллером

---

### Этап 4: Dashboard / Главная страница
**Цель:** Отображение общего состояния системы

**Задачи:**
1. Создать компонент `Dashboard.jsx`
2. Использовать хук `useApi` для получения данных из `/api/state`
3. Создать компонент `StatusCard.jsx` для отображения метрик:
   - NodeID, Role, LinkUp, NetReady, IP, Uptime
4. Создать компонент `DoorsOverview.jsx` — краткая таблица дверей (первые 4-8)
5. Использовать хук `useAutoRefresh` для автообновления каждые 5-10 секунд
6. Обработка состояний загрузки и ошибок

**Результат:** Рабочая главная страница с данными из контроллера

### Этап 5: Мониторинг → Двери
