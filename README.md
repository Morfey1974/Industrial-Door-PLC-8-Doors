# Industrial-Door-PLC
Подробная фиксация итогов “что сделано до этого момента”
0) Базовый запуск и стабильность прошивки

Исправлена проблема запуска: папка Startup была пустая → добавлен startup_stm32h723zgtx.s, после чего плата начала корректно исполнять код, heartbeat стал работать.

1) Doors Bring-Up (GPIO + Alarm + сигнализация)

Сделано и подтверждено на железе:

Все двери по умолчанию unlocked, зелёный (без лишнего шума).

Alarm-кнопка:

1-е нажатие → дверь входит в режим сигнализации

2-е нажатие → выход, возврат к нормальному режиму

Сигнализация соответствует ТЗ:

R/G чередование 1 сек

buzzer в RED фазе

Инвариант подтверждён:

lock запрещён при открытой двери

при закрытой двери в RED фазе lock реально щёлкает

2) UART4 RS-485 Bring-Up (без Modbus)

Подтверждено:

UART4 без инверсии

RS-485 DE на PA15

Инициализация через CubeMX / HAL:

HAL_RS485Ex_Init(&huart4, UART_DE_POLARITY_HIGH, 0, 0)

Двумя платами проверено: мастер/слейв обмен работал (команды ON/OFF).

3) CAN Bring-Up (2 платы)

Подтверждено:

Используется FDCAN1

Битрейт окончательно: 500 kbit/s

Heartbeat + online/offline по таймауту работал:

выдернул CAN → “slave стал offline” (индикатор был красный)

4) QSPI/OCTOSPI Bring-Up

Подтверждено:

Flash реально читает/пишет (в т.ч. тестом переменной blink_ms)

Твой критерий “визуально и понятно” выполнен: поведение LED менялось согласно значению, прочитанному из flash.
