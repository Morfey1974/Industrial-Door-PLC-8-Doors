# Увеличение пула TCP-соединений LwIP

Этап планирования: Решение проблемы "зависания" Web-интерфейса при передергивании Ethernet-кабеля.

## Описание проблемы
Как мы выяснили в ходе анализа, то, что вы описываете (пинг работает, но HTTP-запросы перестают проходить или проходят единично), является классическим следствием **исчерпания пула TCP PCB (Protocol Control Blocks) в LwIP**.

Когда HTTP-запросы прерываются обрывом физического соединения до их корректного закрытия браузером и сервером, старые TCP-соединения остаются висеть в памяти контроллера в состоянии `FIN_WAIT_1` в попытках доставить завершающий пакет (исчерпание таймаута для таких пакетов по умолчанию в TCP LwIP составляет около 12-15 минут!). 

Базовые настройки CubeMX выделяют всего **5 TCP соединений** (`MEMP_NUM_TCP_PCB = 5`). Как только кабель перевключается второй раз подряд, браузер генерирует новые фоновые запросы (зависящие от открытой вкладки с UI), и эти жалкие 5 слотов моментально переполняются зависшими закрывающимися подключениями. Для новых сессий памяти просто не хватает, из-за чего HTTP-сервер замолкает, в то время как ICMP(Ping)-стек, не требующий сессий, продолжает отвечать.

### Настройки LwIP 

#### [MODIFY] [lwipopts.h](file:///c:/Users/morfe/STM32CubeIDE/workspace_1.17.0/Industrial%20Door%20PLC/LWIP/Target/lwipopts.h)
В блок пользовательского кода `USER CODE BEGIN 1` (в конец файла перед `USER CODE END 1`) предлагается добавить макросы, переопределяющие дефолты LwIP, расширяющие ресурсы для активного polling-взаимодействия со стороны браузера.

Текст добавления:
```c
/* Увеличение пулов LwIP для решения исчерпания сокетов при потере линка */

#define MEMP_NUM_TCP_PCB                32
#endif

#ifndef MEMP_NUM_TCP_PCB_LISTEN
#define MEMP_NUM_TCP_PCB_LISTEN         8
#endif

#ifndef MEMP_NUM_TCP_SEG
#define MEMP_NUM_TCP_SEG                64
#endif
```
