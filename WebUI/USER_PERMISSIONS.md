# Система прав доступа пользователей

## Роли пользователей

В системе определены три роли пользователей:

1. **Оператор (operator)**
   - Только просмотр данных
   - Доступ к разделу "Мониторинг" (Двери, События, Алармы, Статистика)
   - Доступ к разделу "Настройки" → "Профиль" (изменение своего пароля)
   - **НЕТ доступа** к разделу "Конфигурация"
   - **НЕТ доступа** к управлению пользователями

2. **Администратор (admin)**
   - Все права оператора
   - Доступ к разделу "Конфигурация" (Настройка дверей)
   - **НЕТ доступа** к разделу "Настройки" → "Параметры системы"
   - **НЕТ доступа** к управлению пользователями

3. **Супер-администратор (super_admin)**
   - Все права администратора
   - **Полный удалённый доступ** к контроллеру — раздел "Настройки" → "Параметры системы" (сеть, безопасность, удалённый доступ)
   - Доступ к разделу "Настройки" → "Пользователи" (создание, редактирование, удаление пользователей)

## Где настраиваются права пользователя?

### 1. При создании пользователя

**Местоположение:** `Настройки` → `Пользователи` → `+ Создать пользователя`

В модальном окне создания пользователя можно указать:
- **Имя пользователя** (уникальное)
- **Пароль** (минимум 8 символов)
- **Роль** (выбор из списка: Оператор, Администратор, Супер-администратор)
- **Включен** (чекбокс для активации/деактивации пользователя)

### 2. При редактировании пользователя

**Местоположение:** `Настройки` → `Пользователи` → кнопка `Редактировать` у нужного пользователя

В модальном окне редактирования можно изменить:
- **Роль** (изменить роль пользователя)
- **Новый пароль** (опционально, оставить пустым, чтобы не менять)
- **Включен** (активировать/деактивировать пользователя)

**Примечание:** Имя пользователя нельзя изменить после создания.

### 3. Управление пользователями

**Доступ:** Только для Супер-администратора

**Функции:**
- Просмотр списка всех пользователей
- Создание новых пользователей
- Редактирование существующих пользователей
- Удаление пользователей (кроме самого себя)
- Просмотр информации о пользователях (дата создания, последний вход)

## Защита маршрутов

Система автоматически защищает маршруты на основе ролей:

- **Мониторинг** (`/monitoring/*`) - доступен всем ролям
- **Конфигурация** (`/configuration/*`) - только для `admin` и `super_admin`
- **Настройки → Профиль** (`/settings/profile`) - доступен всем ролям
- **Настройки → Параметры системы** (`/settings/system`) - только для `super_admin` (полный удалённый доступ)
- **Настройки → Пользователи** (`/settings/users`) - только для `super_admin`

При попытке доступа к недоступной странице:
- Оператор увидит сообщение "Доступ запрещен" с указанием требуемых ролей
- Вкладка "Конфигурация" скрыта для операторов в интерфейсе
- Пункты меню "Параметры системы" и "Пользователи" скрыты для всех, кроме супер-администраторов

## Хранение прав доступа

Права доступа хранятся в QSPI Flash на плате в базе данных пользователей:
- Каждый пользователь имеет поле `role` (тип `user_role_t`)
- Роли определены в `App/config/users_format.h`:
  - `USER_ROLE_SUPER_ADMIN = 0`
  - `USER_ROLE_ADMIN = 1`
  - `USER_ROLE_OPERATOR = 2`

## API для управления пользователями

Все API endpoints для управления пользователями требуют роль `super_admin`:

- `GET /api/users` - список пользователей
- `POST /api/users` - создание пользователя
- `PUT /api/users/:username` - обновление пользователя
- `POST /api/users/:username/delete` - удаление пользователя

Проверка прав выполняется на сервере через функцию `check_super_admin_access()` в `App/system/http_api.c`.
