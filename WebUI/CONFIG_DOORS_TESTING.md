# Инструкция по проверке работоспособности конфигурации дверей

## Дата создания: 2026-01-24

---

## Предварительные требования

1. **Firmware:**
   - Скомпилированная и загруженная прошивка с поддержкой `GET /api/config/full`
   - Контроллер подключен к сети (IP: 192.168.1.50)
   - HTTP сервер работает на MASTER плате

2. **Web UI:**
   - Установлены зависимости: `npm install`
   - Запущен dev-сервер: `npm run dev`
   - Браузер открыт на `http://localhost:3000`

3. **Браузер:**
   - Открыта консоль разработчика (F12) для просмотра логов
   - Включен LocalStorage (по умолчанию включен)

---

## Шаг 1: Проверка загрузки страницы

### Действия:
1. Откройте браузер и перейдите на `http://localhost:3000`
2. Войдите в систему (если требуется)
3. Перейдите в раздел **Конфигурация → Настройка дверей**

### Ожидаемый результат:
- ✅ Страница загружается без ошибок
- ✅ Отображается заголовок "Конфигурация → Настройка дверей"
- ✅ Видны 4 вкладки: "Общие параметры", "Двери", "Зависимости", "Таймауты"
- ✅ Видна панель инструментов с кнопками: "Загрузить с сервера", "Сохранить как...", "Экспорт", "Импорт", "Применить на контроллер"
- ✅ В консоли браузера нет ошибок

### Если есть проблемы:
- Проверьте, что dev-сервер запущен (`npm run dev`)
- Проверьте консоль браузера (F12) на наличие ошибок
- Убедитесь, что все файлы созданы и импорты корректны

---

## Шаг 2: Проверка загрузки конфигурации с сервера

### Действия:
1. На странице конфигурации нажмите кнопку **"📥 Загрузить с сервера"**
2. Дождитесь завершения загрузки

### Ожидаемый результат:
- ✅ Кнопка показывает "Загрузка..." во время запроса
- ✅ Конфигурация загружается с сервера
- ✅ Данные отображаются на вкладке "Общие параметры":
  - Название проекта
  - Глобальный таймаут открытия
  - Информация о конфигурации (версия, seq, количество дверей)
- ✅ В консоли браузера виден запрос `GET /api/config/full` со статусом 200

### Если есть проблемы:
- Проверьте, что контроллер доступен по IP `192.168.1.50`
- Проверьте, что endpoint `GET /api/config/full` реализован в firmware
- Проверьте Network tab в DevTools на наличие ошибок запроса

---

## Шаг 3: Проверка вкладки "Общие параметры"

### Действия:
1. Убедитесь, что активна вкладка "Общие параметры"
2. Измените название проекта на "Тестовая конфигурация"
3. Измените глобальный таймаут открытия на 60000 мс
4. Обратите внимание на индикатор автосохранения

### Ожидаемый результат:
- ✅ Поля редактируются корректно
- ✅ Индикатор автосохранения обновляется (показывает время последнего сохранения)
- ✅ В LocalStorage сохраняется черновик (проверьте в DevTools → Application → LocalStorage → `config_draft`)
- ✅ Валидация работает (попробуйте ввести таймаут меньше 1000 или больше 3600000)

### Проверка LocalStorage:
1. Откройте DevTools (F12)
2. Перейдите в Application → LocalStorage → `http://localhost:3000`
3. Найдите ключ `config_draft`
4. Значение должно быть JSON с вашими изменениями

---

## Шаг 4: Проверка вкладки "Двери"

### Действия:
1. Перейдите на вкладку "Двери"
2. Проверьте отображение существующих дверей (если есть)
3. Нажмите кнопку **"+ Добавить дверь"**
4. Заполните форму:
   - Tech ID: 101
   - Drawing ID: 1
   - Плата: 1
   - Локальная дверь: 1
   - Тип: NC
   - Комментарий: "Тестовая дверь"
5. Нажмите "Сохранить"

### Ожидаемый результат:
- ✅ Модальное окно открывается
- ✅ Поля формы редактируются
- ✅ Global Door ID вычисляется автоматически (ID-1-1)
- ✅ При сохранении дверь добавляется в таблицу
- ✅ Валидация работает (попробуйте создать дубликат Tech ID или пары nodeId+localDoor)
- ✅ Автосохранение срабатывает после добавления

### Проверка валидации:
1. Попробуйте создать дверь с Tech ID, который уже существует
2. Попробуйте создать дверь на той же плате и позиции
3. Ожидайте сообщения об ошибках валидации

### Дополнительные проверки:
- Редактирование существующей двери (кнопка ✏️)
- Удаление двери (кнопка 🗑️)
- Фильтрация по плате (выпадающий список)

---

## Шаг 5: Проверка вкладки "Зависимости"

### Действия:
1. Перейдите на вкладку "Зависимости"
2. Убедитесь, что есть хотя бы 2 двери (если нет - добавьте на вкладке "Двери")
3. Выберите дверь-источник из выпадающего списка "Когда открывается дверь"
4. Отметьте чекбоксами двери, которые должны блокироваться
5. Нажмите "Сохранить зависимость"

### Ожидаемый результат:
- ✅ Выпадающий список содержит все двери
- ✅ При выборе источника отображаются чекбоксы для выбора целей
- ✅ Дверь-источник не может быть выбрана как цель (самоблокировка)
- ✅ После сохранения зависимость появляется в списке
- ✅ Можно редактировать зависимость (кнопка ✏️)
- ✅ Можно удалить зависимость (кнопка 🗑️)

### Проверка валидации:
1. Попробуйте выбрать дверь-источник как цель
2. Ожидайте предупреждение о самоблокировке

---

## Шаг 6: Проверка вкладки "Таймауты"

### Действия:
1. Перейдите на вкладку "Таймауты"
2. Убедитесь, что есть хотя бы одна дверь
3. Измените таймаут post-close для одной из дверей (например, 5000 мс)
4. Нажмите "Сбросить" для проверки сброса
5. Нажмите "Сбросить все" для массового сброса

### Ожидаемый результат:
- ✅ Двери сгруппированы по плате
- ✅ Таблица отображает все двери с их таймаутами
- ✅ Можно редактировать таймаут для каждой двери
- ✅ Кнопка "Сбросить" сбрасывает таймаут конкретной двери
- ✅ Кнопка "Сбросить все" сбрасывает все таймауты (с подтверждением)

---

## Шаг 7: Проверка автосохранения и восстановления

### Действия:
1. Внесите изменения в конфигурацию (например, добавьте дверь)
2. Проверьте LocalStorage (DevTools → Application → LocalStorage)
3. Обновите страницу (F5)
4. Должно появиться диалоговое окно с вопросом о восстановлении черновика
5. Нажмите "OK" для восстановления

### Ожидаемый результат:
- ✅ Изменения сохраняются в LocalStorage автоматически
- ✅ При обновлении страницы появляется диалог восстановления
- ✅ При выборе "OK" черновик восстанавливается
- ✅ При выборе "Отмена" черновик удаляется и загружается конфигурация с сервера

### Проверка LocalStorage:
1. Откройте DevTools (F12) → Application → LocalStorage
2. Найдите ключ `config_draft`
3. Значение должно содержать JSON с вашими изменениями
4. Проверьте поле `timestamp` - должно быть актуальное время

3. Нажмите "OK"
4. Проверьте, что конфигурация появилась в списке "Сохраненные конфигурации"

### Ожидаемый результат:
- ✅ Диалог запрашивает имя конфигурации
- ✅ После сохранения конфигурация появляется в списке
- ✅ В списке отображается количество дверей и дата сохранения
- ✅ Можно загрузить сохраненную конфигурацию (кнопка "Загрузить")
- ✅ Можно удалить сохраненную конфигурацию (кнопка "Удалить")

### Проверка LocalStorage:
1. Проверьте ключ `config_list` - должен содержать список конфигураций

## Шаг 9: Проверка экспорта/импорта

### Экспорт:
1. Нажмите кнопку **"📤 Экспорт"**
2. Должен скачаться JSON файл с именем вида `config_<projectName>.json`
3. Откройте файл в текстовом редакторе
4. Проверьте, что файл содержит корректный JSON с конфигурацией

### Импорт:
1. Нажмите кнопку **"📥 Импорт"**
2. Выберите ранее экспортированный JSON файл
3. Проверьте, что конфигурация загрузилась

### Ожидаемый результат:
- ✅ Экспорт создает валидный JSON файл
- ✅ Импорт загружает конфигурацию из файла
- ✅ При импорте выполняется валидация (попробуйте импортировать невалидный JSON)
- ✅ При успешном импорте показывается сообщение об успехе

### Проверка валидации при импорте:
1. Создайте JSON файл с невалидной конфигурацией (например, с дубликатом Tech ID)
2. Попробуйте импортировать его
3. Ожидайте сообщение об ошибках валидации

### Действия:
1. Убедитесь, что конфигурация валидна (нет ошибок валидации)
2. Нажмите кнопку **"📤 Применить на контроллер"**

## Известные проблемы и ограничения

### 1. PUT /api/config/full - частичная реализация

**Проблема:** Полный парсер JSON для массивов дверей и зависимостей требует доработки.

**Текущее поведение:**
- `GET /api/config/full` - работает полностью
- `PUT /api/config/full` - работает только для базовых полей (projectName, openTimeoutMs)

**Временное решение:**
- Используйте частичное обновление через `PUT /api/config` для базовых полей
- Двери и зависимости можно настраивать через UI, но применение на контроллер будет ограничено

**Проверка:**
1. Попробуйте применить конфигурацию с дверями
2. Проверьте ответ сервера - должно быть предупреждение о частичной реализации
3. Проверьте, что базовые поля (projectName, openTimeoutMs) применились

## Отладка

### Проблемы с загрузкой конфигурации

1. **Проверьте Network tab в DevTools:**
   - Запрос `GET /api/config/full` должен быть со статусом 200
   - Проверьте ответ сервера - должен быть валидный JSON

2. **Проверьте консоль браузера:**
   - Не должно быть ошибок JavaScript
   - Проверьте логи загрузки

3. **Проверьте firmware:**
   - Убедитесь, что endpoint `GET /api/config/full` реализован
   - Проверьте UART вывод для диагностики

### Проблемы с автосохранением

1. **Проверьте LocalStorage:**
   - DevTools → Application → LocalStorage
   - Должен быть ключ `config_draft` с актуальными данными

2. **Проверьте консоль браузера:**
   - Не должно быть ошибок при сохранении в LocalStorage

### Проблемы с валидацией

1. **Проверьте консоль браузера:**
   - Ошибки валидации должны выводиться в консоль
   - Проверьте сообщения об ошибках

2. **Проверьте UI:**
   - Поля с ошибками должны быть выделены красным
   - Должны отображаться сообщения об ошибках
