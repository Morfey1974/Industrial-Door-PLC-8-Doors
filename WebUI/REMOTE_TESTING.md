# Удалённое тестирование с другого компьютера

## Быстрый старт

> **Важно:** Используйте **http://**, не https:// — WebUI пока без SSL. Иначе появится ошибка «Этот сайт не может обеспечить безопасное подключение».

1. **Убедитесь, что оба компьютера в одной сети** (или контроллер доступен по IP).

2. **На компьютере с контроллером** (или где запущен WebUI):
   ```bash
   cd WebUI
   npm run dev
   ```
   В консоли появится что-то вроде:
   ```
   ➜  Local:   http://localhost:3000/
   ➜  Network: http://192.168.1.100:3000/
   ```

3. **На другом компьютере** откройте в браузере (обязательно **http://**, не https):
   ```
   http://192.168.1.100:3000/
   ```
   (подставьте IP компьютера с запущенным WebUI из строки Network)

4. **Укажите адрес контроллера** на странице входа (кнопка «Подключение к контроллеру»):

   - Нажмите «Подключение к контроллеру»
   - Введите IP и порт контроллера (например: `192.168.1.50:80` или `http://192.168.1.50:8080`)
   - Нажмите «Сохранить»
   - Выполните вход

5. **Вход:** логин `admin`, пароль `admin` (5 символов — достаточно для входа). Ограничение «минимум 8 символов» применяется только при смене пароля.

## Варианты подключения

### Через URL-параметр (без сохранения)
```
http://192.168.1.100:3000/?controller=http://192.168.1.50:80
```

### Через сохранённые настройки
1. На странице входа нажмите «Подключение к контроллеру»
2. Введите адрес контроллера
3. Сохраните — адрес сохранится в localStorage браузера

## Порядок выбора адреса контроллера

1. URL-параметр `?controller=` или `?api=`
2. Сохранённый в localStorage (`plc_controller_url`)
3. Значения из сборки (`VITE_API_BASE_URL`, `VITE_API_PORT`)

## Сборка для продакшена

При сборке можно задать адрес по умолчанию:
```bash
VITE_API_BASE_URL=http://192.168.1.50 VITE_API_PORT=80 npm run build
```

Собранные файлы в `dist/` можно раздать любым веб-сервером (nginx, Apache) или открыть через `npm run preview`.

## Не подключается с другого компьютера — что проверить

### 1. Доступ к WebUI (порт 3000)

| Проблема | Решение |
|----------|---------|
| **Firewall блокирует порт** | Windows: Панель управления → Брандмауэр → Дополнительные параметры → Правила для входящих подключений → Создать правило → Порт TCP 3000 → Разрешить подключение |
| **Неверный IP** | Выполните `ipconfig` (Windows) — используйте IPv4 из нужной сети (192.168.1.X), не localhost |
| **Нет строки Network в консоли** | В `vite.config.js` должно быть `server: { host: true }` |
| **Проверка с того же ПК** | Откройте `http://ваш-IP:3000` (не localhost) на компьютере с запущенным WebUI |

### 2. Подключение к контроллеру

| Проблема | Решение |
|----------|---------|
| **Контроллер недоступен** | `ping IP_контроллера` — должен отвечать |
| **Неверный порт** | По умолчанию 80. Если меняли в «Параметры системы» — укажите правильный порт |
| **Разные подсети** | WebUI-ПК и контроллер должны быть в одной сети (192.168.1.X) |

### 3. Быстрые команды (PowerShell)

```powershell
# IP адрес этого компьютера
ipconfig | findstr "IPv4"

# Проверка, слушает ли порт 3000
netstat -an | findstr "3000"

# Проверка доступа к контроллеру
ping 192.168.1.50
```

### 4. «Этот сайт не может обеспечить безопасное подключение»

Браузер пытается открыть страницу по **HTTPS**, а WebUI работает только по **HTTP**.

**Решение:** Вводите адрес с явным указанием **http://**:
```
http://192.168.1.100:3000
```
Не используйте `https://` — контроллер и dev‑сервер пока без SSL.

**Chrome/Edge:** при автоподстановке https вручную замените на `http://`.

### 5. Частые ошибки

1. **Firewall** — самая частая причина: порт 3000 закрыт
2. **HTTPS вместо HTTP** — используйте `http://`, не `https://`
3. **Перепутали IP** — в «Подключение к контроллеру» указывается IP **контроллера**, а не компьютера с WebUI
4. **Разные сети** — WiFi и Ethernet на разных подсетях, или гостевая сеть Wi-Fi

### 6. Изоляция Wi‑Fi — удалённый ПК не видит контроллер

Если удалённый компьютер по Wi‑Fi (ping не проходит, `http://IP_контроллера/api/state` не открывается), а подключить кабелем невозможно:

**Решение: прокси на локальном ПК**

1. **На локальном ПК** (который подключён к контроллеру) запустите прокси:
   ```bash
   cd WebUI
   npm run proxy
   ```
   Или с параметрами (порт 3080, контроллер 192.168.1.50:80):
   ```bash
   node proxy.cjs 3080 192.168.1.50:80
   ```

2. **Убедитесь, что порт 3080 открыт** в брандмауэре (аналогично порту 3000).

3. **На удалённом ПК** откройте WebUI (`http://IP_локального_ПК:3000`), нажмите «Подключение к контроллеру» и укажите:
   ```
   http://IP_локального_ПК:3080
   ```
   Например: `http://192.168.1.130:3080`

4. **Выполните вход** — запросы пойдут через прокси: удалённый браузер → локальный ПК → контроллер.

## Доступ из другого города (VPN)

Чтобы подключаться к контроллеру из другого города (через интернет), нужен VPN: вы «оказываетесь» в домашней/офисной сети и используете те же адреса 192.168.1.x.

### Вариант A: VPN-сервер на роутере

1. Зайдите в веб-интерфейс роутера (обычно http://192.168.1.1).
2. Найдите раздел VPN (WireGuard, OpenVPN или встроенный VPN-сервер).
3. Включите VPN-сервер, создайте пользователя или сгенерируйте ключ/конфиг.
4. С телефона или ноутбука из другого города установите клиент (WireGuard, OpenVPN и т.п.) и подключитесь по выданному конфигу или ключу.
5. После подключения откройте в браузере `http://IP_ПК_с_WebUI:3000` (тот же IP, что и в локальной сети) и в «Подключение к контроллеру» укажите контроллер или прокси.

### Вариант B: VPN на ПК (где запущен WebUI)

1. На ПК установите VPN-сервер (WireGuard или OpenVPN).
2. На роутере настройте переадресацию порта VPN на этот ПК (например порт 51820 для WireGuard).
3. Узнайте внешний IP дома (или настройте динамический DNS — No-IP, DuckDNS).
4. С удалённого устройства подключайтесь к VPN по внешнему IP или домену.
5. После подключения откройте `http://192.168.1.130:3000` (или IP ПК в VPN) и укажите контроллер/прокси.

### Вариант C: Tailscale или ZeroTier

1. Установите Tailscale (или ZeroTier) на ПК в сети и на телефон/ноутбук.
2. Войдите в один аккаунт на обоих устройствах — они окажутся в одной виртуальной сети.
3. Tailscale выдаст ПК свой IP (например 100.x.x.x). Откройте в браузере `http://100.x.x.x:3000` (подставьте IP из приложения Tailscale).
4. В «Подключение к контроллеру» укажите контроллер по его локальному IP или прокси по IP ПК в Tailscale (100.x.x.x:3080).

**Рекомендация:** Tailscale/ZeroTier не требуют переадресации портов и настройки роутера — удобно для быстрого доступа.

### 7. «admin / admin» не пускает

| Причина | Решение |
|---------|---------|
| **Неверный адрес контроллера** | Проверьте «Подключение к контроллеру» — IP и порт контроллера (например, 192.168.1.50:80). |
| **Контроллер недоступен** | Откройте в браузере `http://IP:порт/api/state` — должен вернуться JSON. Если нет — контроллер не отвечает. |
| **«Ошибка подключения к серверу»** | Связь с контроллером не установлена — проверьте IP, порт и сеть. |
| **Пароль 8+ символов** | Не нужен: для входа пароль `admin` (5 символов) подходит. Минимум 8 символов — только при смене пароля. |
