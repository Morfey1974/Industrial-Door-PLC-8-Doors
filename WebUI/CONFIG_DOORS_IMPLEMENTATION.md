# Реализация конфигурации дверей - Описание

## Дата создания: 2026-01-24

---

## Обзор

Реализован полнофункциональный Web-интерфейс для конфигурирования дверей в системе Industrial Door PLC. Интерфейс позволяет создавать, редактировать, сохранять и применять конфигурации дверей с поддержкой множества плат (MASTER + SLAVE), зависимостей между дверями и индивидуальных таймаутов.

---

## Реализованные компоненты

### 1. Основная страница конфигурации

**Файл:** `WebUI/src/pages/Configuration/DoorsConfig.jsx`

**Функциональность:**
- Управление состоянием конфигурации
- Загрузка конфигурации с сервера
- Автосохранение в LocalStorage
- Восстановление черновика при загрузке
- Сохранение именованных конфигураций
- Экспорт/импорт JSON файлов
- Применение конфигурации на контроллер
- Валидация перед применением

**Вкладки:**
1. **Общие параметры** - название проекта, глобальный таймаут
2. **Двери** - таблица всех дверей с редактированием
3. **Зависимости** - настройка зависимостей между дверями
4. **Таймауты** - индивидуальные таймауты post-close

---

### 2. Утилиты автосохранения

**Файл:** `WebUI/src/utils/configStorage.js`

**Функции:**
- `saveDraft(config)` - сохранение черновика в LocalStorage
- `loadDraft()` - загрузка черновика
- `clearDraft()` - удаление черновика
- `saveNamedConfig(name, config)` - сохранение именованной конфигурации
- `loadNamedConfig(name)` - загрузка именованной конфигурации
- `deleteNamedConfig(name)` - удаление именованной конфигурации
- `getSavedConfigsList()` - список всех сохраненных конфигураций
- `exportConfigToFile(config, filename)` - экспорт в JSON файл
- `importConfigFromFile(file)` - импорт из JSON файла

**Ключи LocalStorage:**
- `config_draft` - черновик конфигурации
- `config_list` - список сохраненных конфигураций
- `config_saved_<name>` - именованная конфигурация
- `config_current_name` - имя текущей конфигурации

---

### 3. Валидация конфигурации

**Файл:** `WebUI/src/utils/configValidator.js`

**Функции:**
- `validateConfig(config)` - полная валидация конфигурации
- `validateDoor(door, existingDoors)` - валидация отдельной двери
- `calculateGlobalDoorId(nodeId, localDoor)` - вычисление globalDoorId

**Проверки:**
- Название проекта (не пустое, максимум 32 символа)
- Глобальный таймаут (от 1000 до 3600000 мс)
- Количество дверей (максимум 80)
- Уникальность TechId
- Уникальность пары nodeId+localDoor
- Корректность nodeId (1-10) и localDoor (1-8)
- Тип двери (NC, NO, CARD_READER)
- Длина комментария (максимум 32 символа)
- Зависимости (проверка существования дверей, отсутствие циклов)
- Таймауты post-close (от 0 до 3600000 мс)

---

### 4. Вкладка "Общие параметры"

**Файл:** `WebUI/src/pages/Configuration/DoorsConfigTabs/GeneralTab.jsx`

**Функциональность:**
- Редактирование названия проекта
- Редактирование глобального таймаута открытия
- Отображение информации о конфигурации:
  - Версия формата
  - Последовательный номер (seq)
  - Количество дверей
  - Количество зависимостей

---

### 5. Вкладка "Двери"

**Файл:** `WebUI/src/pages/Configuration/DoorsConfigTabs/DoorsTab.jsx`

**Функциональность:**
- Таблица всех дверей с колонками:
  - Плата (nodeId)
  - Дверь (localDoor)
  - Global ID (ID-nodeId-localDoor)
  - Tech ID
  - Drawing ID
  - Тип
  - Комментарий
- Фильтрация по плате
- Добавление новой двери (автоматический поиск свободной позиции)
- Редактирование двери (модальное окно)
- Удаление двери (с проверкой зависимостей)

**Модальное окно редактирования:**
- Tech ID (обязательное, уникальное)
- Drawing ID (опционально)
- Плата (Node ID, 1-10)
- Локальная дверь (1-8)
- Global Door ID (вычисляется автоматически)
- Тип двери (NC, NO, CARD_READER)
- Комментарий (максимум 32 символа)
- Валидация в реальном времени

---

### 6. Вкладка "Зависимости"

**Файл:** `WebUI/src/pages/Configuration/DoorsConfigTabs/DependenciesTab.jsx`

**Функциональность:**
- Выбор двери-источника (когда открывается)
- Выбор дверей-целей (блокируемых) через чекбоксы
- Список всех зависимостей с группировкой по источнику
- Редактирование зависимости
- Удаление зависимости
- Проверка на самоблокировку

**Формат зависимости:**
- `srcGlobalDoorId` - дверь-источник (когда открывается)
- `dstGlobalDoorId` - дверь-цель (блокируется)

---

### 7. Вкладка "Таймауты"

**Файл:** `WebUI/src/pages/Configuration/DoorsConfigTabs/TimeoutsTab.jsx`

**Функциональность:**
- Отображение глобального таймаута открытия
- Таблица всех дверей с индивидуальными таймаутами post-close
- Группировка дверей по плате
- Редактирование таймаута для каждой двери
- Сброс таймаута для отдельной двери
- Массовый сброс всех таймаутов

---

### 8. API расширения (Firmware)

**Файл:** `App/system/http_api.c`

**Новые endpoints:**
- `GET /api/config/full` - получение полной конфигурации (все двери, зависимости, таймауты)
- `PUT /api/config/full` - сохранение полной конфигурации

**Функции:**
- `build_config_full()` - построение JSON с полной конфигурацией
- `put_config_full()` - парсинг и сохранение полной конфигурации

**Примечание:** Полный парсер JSON для массивов дверей и зависимостей требует доработки. Пока реализована базовая структура для основных полей.

## Автосохранение и восстановление

### Механизм автосохранения

1. **Черновик (Draft):**
   - Автоматически сохраняется в LocalStorage при каждом изменении
   - Ключ: `config_draft`
   - Содержит timestamp последнего изменения
   - Восстанавливается при загрузке страницы (с подтверждением)

2. **Именованные конфигурации:**
   - Сохраняются в LocalStorage с ключом `config_saved_<name>`
   - Список хранится в `config_list`
   - Можно загрузить, удалить, экспортировать

3. **Экспорт/импорт:**
   - Экспорт в JSON файл через браузер
   - Импорт из JSON файла с валидацией
   - Используется для резервного копирования

## Валидация

### Клиентская валидация

Выполняется перед отправкой на сервер:
- Проверка всех обязательных полей
- Проверка диапазонов значений
- Проверка уникальности
- Проверка корректности зависимостей

### Серверная валидация

Выполняется в firmware через `Config_Validate()`:
- Проверка формата конфигурации
- Проверка бизнес-правил
- Проверка целостности данных

## Особенности реализации

### 1. Поддержка множества плат

- Отображение дверей с разных плат (MASTER + SLAVE)
- Фильтрация по плате
- Группировка по плате в таймаутах
- Global Door ID вычисляется автоматически: `(nodeId - 1) * 8 + localDoor`

### 2. Зависимости между дверями

- Визуальный редактор с выбором через чекбоксы
- Группировка зависимостей по источнику
- Проверка на самоблокировку
- Автоматическое удаление зависимостей при удалении двери

### 3. Индивидуальные таймауты

- Группировка по плате для удобства
- Массовое редактирование
- Сброс к значению по умолчанию (0)

### 4. Автосохранение

- Сохранение при каждом изменении
- Восстановление при загрузке страницы
- Индикатор последнего сохранения
- Защита от потери данных при сбое

## Ограничения и известные проблемы

### 1. Парсер полной конфигурации в firmware

**Проблема:** Полный парсер JSON для массивов дверей и зависимостей требует доработки.

**Текущее состояние:**
- `GET /api/config/full` - работает (возвращает полную конфигурацию)
- `PUT /api/config/full` - частично работает (только базовые поля: projectName, openTimeoutMs)

**Решение:**
- Пока можно использовать частичное обновление через `PUT /api/config`
- Полный парсер можно реализовать позже или использовать существующий JSON парсер с расширением

### 2. Размер буфера HTTP

**Ограничение:** Буфер ответа 8KB может быть недостаточен для очень больших конфигураций (80 дверей + 256 зависимостей).

**Решение:** При необходимости можно увеличить буфер или реализовать chunked transfer.
