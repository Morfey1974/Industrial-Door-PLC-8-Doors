# Отчёт об оптимизации и стабилизации сети (Ethernet/HTTP)

Данный документ суммирует изменения, внесённые для устранения нестабильности и ускорения работы Web UI.

## 1. Устранение "падения" сети через 30-40 секунд
**Проблема:** Исчерпание пула TCP PCB из-за большого количества соединений в состоянии `TIME_WAIT`. Дефолтный таймаут 120 сек был слишком велик для частого опроса.

**Изменения в `lwipopts.h`:**
*   `TCP_MSL = 1000` — Сократило время `TIME_WAIT` до **2 секунд**.
*   `MEMP_NUM_TCP_PCB = 32` — Увеличен пул соединений.
*   `MEMP_NUM_NETCONN = 16` — Увеличен пул структур сокетов.

## 2. Повышение скорости передачи данных
**Проблема:** Маленькие буферы и алгоритм Нагла вызывали задержки в доставке JSON-ответов.

**Изменения:**
*   **`lwipopts.h`**: `MEM_SIZE` увеличен до **8 КБ**, `TCP_SND_BUF` до **4 пакетов MSS**. Это позволило TCP стеку держать в памяти больше данных для отправки.
*   **`http_server.c`**: Включена опция `TCP_NODELAY`. Данные теперь улетают мгновенно, не дожидаясь заполнения пакета.
*   **`http_server.c`**: Размер чанка в `lwip_send` увеличен с 512 до **1460 байт (MSS)**. Количество итераций для отправки состояния двери сократилось в 3 раза.

## 3. Оптимизация отзывчивости (Latency)
**Проблема:** Сериализация запросов и большие задержки опроса в интерфейсе.

**Изменения:**
*   **`http_task.c`**: Убрана безусловная пауза `osDelay(10)`. Если сервер обработал клиента, он сразу проверяет наличие следующего. Это позволяет "проглатывать" пачки запросов от браузера мгновенно.
*   **`WebUI/src/utils/constants.js`**: Интервал опроса статуса (`HEADER_STATE_POLL_MS`) снижен с 2500 мс до **800 мс**.
*   **`WebUI/src/pages/Mapping.jsx`**: Интервал в режиме просмотра снижен с 800 мс до **400 мс**.

## Итог
- **Надёжность:** Сеть больше не "отваливается" при длительной работе Web UI.
- **Скорость:** Визуальная реакция на изменение статуса дверей стала практически мгновенной (< 1 сек).
- **Производительность:** Нагрузка на CPU минимизирована за счет оптимального использования TCP пакетов (MSS).
