# Анализ использования памяти и буферов

## Размеры буферов HTTP сервера

### Приём запросов
- **`HTTP_RX_BUF_SZ`**: 768 байт
  - Используется для приёма HTTP запросов
  - Достаточно для стандартных GET/PUT запросов
  - Расположение: стек задачи `httpTask`

### Отправка ответов
- **Буфер ответа GET**: 4096 байт (увеличен с 2048)
  - Используется для формирования JSON ответов
  - Особенно важен для `/api/doors` с 8 дверьми (~900 байт JSON)
  - Расположение: локальная переменная в `http_send_simple()`
  - **Примечание**: Увеличен до 4096 для обеспечения запаса при расширении API

### Приём тела запроса (PUT)
- **`HTTP_BODY_MAX`**: 2048 байт
  - Используется для приёма JSON тела в PUT запросах
  - Достаточно для загрузки конфигурации
  - Расположение: локальная переменная в обработчике PUT

### Вспомогательные буферы
- **Заголовки HTTP**: 256 байт
  - Используется для формирования HTTP заголовков
  - Расположение: локальная переменная в `http_send_simple()`

## Размеры стеков задач (FreeRTOS)

### HTTP задача
- **`httpTask`**: 2048 * 4 = **8192 байт**
  - Самая большая задача по стеку
  - Обоснование: обработка HTTP запросов, JSON формирование, работа с сокетами

### Сетевые задачи
- **`netTask`**: 768 * 4 = **3072 байт**
  - Управление сетью (LwIP)
  
### Задачи управления
- **`doorsTask`**: 512 * 4 = **2048 байт**
  - Управление дверями, обработка событий
  
- **`commsTask`**: 512 * 4 = **2048 байт**
  - Logic Core, обработка команд
  
- **`supervisorTask`**: 512 * 4 = **2048 байт**
  - Надзор за системой
  
- **`canTask`**: 512 * 4 = **2048 байт**
  - CAN протокол
  
- **`rs485Task`**: 512 * 4 = **2048 байт**
  - RS-485 протокол
  
- **`loggerTask`**: 512 * 4 = **2048 байт**
  - Логирование
  
- **`watchdogTask`**: 512 * 4 = **2048 байт**
  - Watchdog
  
- **`journalTask`**: 512 * 4 = **2048 байт**
  - Журнал событий

### Итого стеков задач
- **Общий размер стеков**: ~28 KB
- **Самый большой стек**: `httpTask` (8 KB)

## Общий heap (FreeRTOS)

- **`configTOTAL_HEAP_SIZE`**: 65536 байт (64 KB)
  - Используется для динамического выделения памяти FreeRTOS
  - Мьютексы, семафоры, очереди создаются из этого heap

## Буферы в других модулях

### UART3 CLI
- **`UART3_CLI_LINE_MAX`**: 128 байт
  - Максимальная длина команды CLI
- **Пул команд**: 4 * 128 = 512 байт
  - Пул готовых строк для CLI

### Логирование
- **`APP_LOG_MSG_MAX`**: размер сообщения лога
  - Используется в очереди логов

### JSON парсер
- **Временные буферы**: до 64 байт
  - Используются для парсинга JSON в PUT запросах

## Рекомендации по оптимизации

### Возможные оптимизации

1. **HTTP буфер ответа (4096 байт)**
   - Текущий размер: достаточен для 8 дверей (~900 байт JSON)
   - Запас: ~3.5 KB для будущих расширений
   - **Рекомендация**: Оставить 4096 байт для обеспечения запаса

2. **HTTP буфер приёма (768 байт)**
   - Текущий размер: достаточен для стандартных запросов
   - **Рекомендация**: Оставить без изменений

3. **Стек `httpTask` (8192 байт)**
   - Текущий размер: самый большой стек
   - Обоснован: работа с сокетами, JSON, буферы
   - **Рекомендация**: Оставить без изменений, но мониторить использование

4. **Стеки других задач (2048 байт)**
   - Текущий размер: стандартный для большинства задач
   - **Рекомендация**: Оставить без изменений

### Мониторинг использования памяти

**Реализовано:** Команда CLI `mem stat` для вывода реальных данных об использовании памяти.

**Использование:**
1. Открыть UART монитор (UART3, 115200 baud)
2. Ввести команду: `mem stat`
3. Получить вывод:
   - Статистика heap (FreeRTOS): общий размер, свободно, использовано, минимум свободной памяти
   - Статистика стеков всех задач: использовано/размер для каждой задачи в процентах

**Пример вывода:**
```
=== Memory Statistics ===
Heap (FreeRTOS):
  Total:     65536 bytes
  Free:      45000 bytes
  Used:      20536 bytes (31.3%)
  Min free:  42000 bytes (max used: 23536, 35.9%)
Task Stacks:
  netTask        :  1200/ 3072 bytes used (39.1%)
  commsTask      :   800/ 2048 bytes used (39.1%)
  doorsTask      :   600/ 2048 bytes used (29.3%)
  supervisorTask :   500/ 2048 bytes used (24.4%)
  httpTask       :  3500/ 8192 bytes used (42.7%)
  canTask        :   400/ 2048 bytes used (19.5%)
  rs485Task      :   300/ 2048 bytes used (14.6%)
  loggerTask     :   200/ 2048 bytes used ( 9.8%)
  watchdogTask   :   150/ 2048 bytes used ( 7.3%)
  journalTask    :   400/ 2048 bytes used (19.5%)
```

**Функции FreeRTOS:**
- `xPortGetFreeHeapSize()` - текущая свободная память heap
- `xPortGetMinimumEverFreeHeapSize()` - минимум свободной памяти за всё время
- `uxTaskGetStackHighWaterMark()` - минимум свободного стека задачи (в словах, 4 байта на Cortex-M)

## Выводы

1. **Текущее использование памяти**: в пределах нормы
2. **Буферы**: размеры достаточны для текущих задач
3. **Запас**: есть запас для будущих расширений
4. **Рекомендация**: добавить мониторинг использования памяти через CLI

## Примечание о буфере 4096 байт

Буфер ответа HTTP увеличен до **4096 байт** для обеспечения:
- Корректной работы `/api/doors` с 8 дверьми (~900 байт JSON)
- Запаса для будущих расширений API
- Предотвращения переполнения буфера при добавлении новых полей

Это изменение зафиксировано в `App/system/http_server.c`:
```c
char body[4096];  // Увеличен с 2048 для JSON с 8 дверьми
```
