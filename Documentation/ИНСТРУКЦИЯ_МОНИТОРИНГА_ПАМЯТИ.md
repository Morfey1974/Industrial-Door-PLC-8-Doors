# Инструкция по мониторингу использования памяти

## Команда `mem stat`

Добавлена команда CLI для вывода реальных данных об использовании памяти в системе.

### Использование

1. Открыть UART монитор (UART3, 115200 baud)
2. Ввести команду: `mem stat`
3. Получить подробную статистику по памяти

### Что показывает команда

#### 1. Heap (FreeRTOS)
- **Total** - общий размер heap (65536 байт = 64 KB)
- **Free** - текущая свободная память
- **Used** - используемая память в байтах и процентах
- **Min free** - минимальная свободная память за всё время работы
- **Max used** - максимальная использованная память за всё время

#### 2. Task Stacks
Для каждой задачи показывает:
- Имя задачи
- Использовано/Размер стека в байтах
- Процент использования стека

### Пример вывода

```
=== Memory Statistics ===
Heap (FreeRTOS):
  Total:     65536 bytes
  Free:      45000 bytes
  Used:      20536 bytes (31.3%)
  Min free:  42000 bytes (max used: 23536, 35.9%)
Task Stacks:
  netTask        :  1200/ 3072 bytes used (39.1%)
  commsTask      :   800/ 2048 bytes used (39.1%)
  doorsTask      :   600/ 2048 bytes used (29.3%)
  supervisorTask :   500/ 2048 bytes used (24.4%)
  httpTask       :  3500/ 8192 bytes used (42.7%)
  canTask        :   400/ 2048 bytes used (19.5%)
  rs485Task      :   300/ 2048 bytes used (14.6%)
  loggerTask     :   200/ 2048 bytes used ( 9.8%)
  watchdogTask   :   150/ 2048 bytes used ( 7.3%)
  journalTask    :   400/ 2048 bytes used (19.5%)
```

### Анализ результатов

#### Heap
- Если **Used** близко к 100% - система близка к нехватке памяти
- Если **Min free** очень мало - были моменты критической нехватки памяти
- Рекомендуется оставлять запас минимум 20-30%

#### Task Stacks
- Если использование стека > 80% - **опасно**, возможен stack overflow
- Если использование стека > 60% - рекомендуется увеличить размер стека
- Если использование стека < 30% - можно уменьшить размер стека для экономии памяти

### Рекомендации по оптимизации

#### 1. Если `httpTask` использует < 50% стека
Можно уменьшить размер стека с 8192 до 6144 байт (1536 * 4):
```c
// В Core/Src/freertos.c
const osThreadAttr_t httpTask_attributes = {
  .name = "httpTask",
  .stack_size = 1536 * 4,  // Было: 2048 * 4
  .priority = (osPriority_t) osPriorityNormal,
};
```

#### 2. Если другие задачи используют < 30% стека
Можно уменьшить размер стека с 2048 до 1536 байт (384 * 4):
```c
// В Core/Src/freertos.c
const osThreadAttr_t doorsTask_attributes = {
  .name = "doorsTask",
  .stack_size = 384 * 4,  // Было: 512 * 4
  .priority = (osPriority_t) osPriorityLow,
};
```

#### 3. Если heap используется < 40%
Можно уменьшить `configTOTAL_HEAP_SIZE` в `Core/Inc/FreeRTOSConfig.h`:
```c
#define configTOTAL_HEAP_SIZE ((size_t)49152)  // Было: 65536 (48 KB вместо 64 KB)
```

**ВАЖНО:** После изменения размеров стеков или heap обязательно:
1. Перекомпилировать проект
2. Прошить плату
3. Запустить `mem stat` несколько раз в разных режимах работы
4. Убедиться, что использование не превышает 70-80%

### Другие команды CLI

- `log help` - справка по командам журнала
- `log stat` - статистика журнала событий
- `log dump [N]` - дамп последних N записей журнала
- `log clear` - очистка журнала
- `mem stat` - статистика памяти (новая команда)

### Технические детали

Команда использует функции FreeRTOS:
- `xPortGetFreeHeapSize()` - текущая свободная память heap
- `xPortGetMinimumEverFreeHeapSize()` - минимум свободной памяти за всё время
- `uxTaskGetStackHighWaterMark()` - минимум свободного стека задачи

Функция `uxTaskGetStackHighWaterMark()` возвращает количество **слов** (4 байта на Cortex-M), поэтому результат умножается на 4 для получения байт.
