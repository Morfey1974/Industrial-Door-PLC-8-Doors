# Резюме по RTC (DS3231) — передача в новый чат

## Цель
Подключить внешний RTC DS3231 (I2C1, PB6/PB7), выводить время по UART3 периодически; в перспективе — синхронизация времени из UI и отображение в отчётах/статистике. Проект — управление дверями с UI (FreeRTOS, STM32H723).

---

## Что сделано и работает

1. **Железо и конфиг**
   - I2C1 в .ioc: PB6 (SCL), PB7 (SDA), 100 kHz, 7-bit.
   - Драйвер DS3231: `App/drivers/ds3231.c`, `ds3231.h` — чтение даты/времени (BCD → десятичный), `DS3231_ReadDateTime()`.

2. **Тик FreeRTOS из TIM6**
   - SysTick в этой конфигурации не использовался для тика.
   - В `main.c` в `HAL_TIM_PeriodElapsedCallback(htim)` при `htim->Instance == TIM6` вызывается `xPortSysTickHandler()` (и `HAL_IncTick()`).
   - В `FreeRTOSConfig.h`: `USE_CUSTOM_SYSTICK_HANDLER_IMPLEMENTATION 1`; в `stm32h7xx_it.c` свой `SysTick_Handler` только сбрасывает флаг, тик не вызывает.

3. **Задача RTC**
   - `App/system/rtc_test_task.c`: при старте один раз читает RTC и выводит `[0]`, затем цикл `for(;;)` с `vTaskDelay(2000)` и повторное чтение/вывод `[1]`, `[2]`, …
   - Задача создаётся **первой** в `Core/Src/freertos.c` (до netTask и др.), приоритет `osPriorityAboveNormal` (32) — в этом порте FreeRTOS **больший номер = выше приоритет** (idle=0, normal=24).

4. **Маркеры отладки (пока не убирать)**
   - В задаче: `RTC: start` (вход), `L0` (после [0]), `L1` (перед vTaskDelay), `L2` (после vTaskDelay), `L3` (после вывода [n]).
   - В драйвере DS3231: `D0`, `D1`, `D2` (вход в ReadDateTime, до/после Mem_Read).
   - В callback TIM6 (main.c): один раз `RTC: T6`.

5. **Документация**
   - `Documentation/DS3231_RTC_Setup.md` — подключение и настройка.

---

## Проблема (не решена)

**Задача доходит до L1 и не выходит из `vTaskDelay(pdMS_TO_TICKS(2000))` — L2, [1], [2] не появляются.**

Текущий вывод в мониторе:
```
RTC: T6
RTC: start
RTC: D0
RTC: D1
RTC: D2
RTC: [0] 2000-01-01 02:32:45
RTC: L0
RTC: L1
```
(далее тишина)

То есть:
- Тик из TIM6 идёт (T6 есть).
- Задача запускается (start, D0–D2, [0], L0, L1).
- После входа в `vTaskDelay(2000)` задача не получает управление снова — переключение контекста по истечении задержки не происходит (или задача не выбирается планировщиком).

---

## Что уже пробовали

1. **Источник тика**
   - Свой `SysTick_Handler` в `stm32h7xx_it.c` — тик всё равно не «оживлял» задержки.
   - Перенос тика на TIM6 (`xPortSysTickHandler()` в `HAL_TIM_PeriodElapsedCallback`) — тик пошёл (T6), но выход из `vTaskDelay` так и не произошёл.

2. **Приоритет задачи RTC**
   - В этом порте FreeRTOS: **больший номер приоритета = выше приоритет**.
   - Пробовали: `osPriorityAboveNormal` (32), `osPriorityLow` (8), число 4. При 8 и 4 задача вообще не выводила start/D0 (не получала CPU). Вернули `osPriorityAboveNormal` (32).

3. **Порядок создания**
   - Задача RTC создаётся первой в `MX_FREERTOS_Init` (до netTask и остальных).

4. **Переключение контекста из TIM6**
   - После `xPortSysTickHandler()` в callback TIM6 добавлен `portYIELD_FROM_ISR(pdTRUE)` (в main.c подключён `portmacro.h`) — без эффекта.

5. **Программный таймер FreeRTOS**
   - Периодический вывод переводили на `xTimerCreate` + callback — callback таймера **никогда не вызывался** (CB0 не появлялся), при этом T6, T0–T3 были. Отказались в пользу цикла с `vTaskDelay` в задаче.

6. **Стеки и буферы**
   - `configTIMER_TASK_STACK_DEPTH` увеличен до 512 (когда использовали таймер).
   - Стек задачи RTC: 384*4 байт.

## Идеи для продолжения (новый чат)

1. **Проверить, что тик действительно продвигает задержки**
   - В другой задаче (например, с приоритетом 24) вызвать `vTaskDelay(pdMS_TO_TICKS(500))` и маркер после неё — выходит ли задача из задержки. Так станет ясно, проблема в «тик + задержки» или только в задаче RTC.

2. **Проверить приоритеты и PendSV**
   - Убедиться, что PendSV вызывается после тика (например, счётчик в обработчике PendSV или отладочный вывод).
   - Проверить приоритеты прерываний TIM6 и PendSV в NVIC (должны позволять выполнение PendSV после возврата из TIM6).

3. **Альтернатива vTaskDelay**
   - Блокировка задачи на очереди/семафоре с таймаутом 2000 ms (например, `xQueueReceive(..., pdMS_TO_TICKS(2000))`) и подача в очередь из другой задачи или таймера — проверить, выходит ли RTC-задача по таймауту.

4. **Минимальный тест тика**
   - Отдельная задача с приоритетом 32: только `for(;;) { vTaskDelay(500); маркер в UART; }` — если маркер не идёт, проблема общая (тик/планировщик); если идёт — искать причину именно в контексте текущей задачи RTC (стек, прерывания, блокировки).

5. **Проверить порт FreeRTOS**
   - Используется порт GCC/ARM_CM4F; для H7 иногда используют ARM_CM7. Уточнить, что порт и настройки (в т.ч. для вызова тика из TIM6, а не SysTick) рекомендованы для этой конфигурации.

## Важно не сломать

- Остальная логика: двери, UI, сеть, конфиг — не трогать.
- Маркеры в RTC (start, L0–L3, D0–D2, T6) оставить до стабильного появления L2 и периодических [1], [2], …
