## Критическая проблема: httpTask

### Текущее состояние
- **Использование стека**: 7404/8192 байт (90.3%)
- **Свободно**: только 788 байт
- **Статус**: ⚠️ **КРИТИЧЕСКИ ОПАСНО** - высокий риск stack overflow!

### Причины высокого использования стека

В `http_server.c` на стеке выделяются большие буферы:

1. **`body[4096]`** - 4096 байт (в функции обработки GET запросов)
2. **`rx[HTTP_RX_BUF_SZ]`** - 768 байт (буфер приёма запросов)
3. **`hdr[256]`** - 256 байт (буфер заголовков HTTP, используется дважды)
4. **`req_body[HTTP_BODY_MAX]`** - 2048 байт (буфер тела PUT запроса)
5. **`resp[768]`** - 768 байт (буфер ответа)
6. **Локальные переменные** - ~100-200 байт
7. **Стек вызовов функций** - ~200-300 байт

**Итого**: ~8200+ байт на стеке, что близко к лимиту 8192 байт.

### Решения

#### Вариант 1: Увеличить стек httpTask (рекомендуется)

В `Core/Src/freertos.c`:
```c
const osThreadAttr_t httpTask_attributes = {
  .name = "httpTask",
  .stack_size = 3072 * 4,  // Было: 2048 * 4, Стало: 12288 байт
  .priority = (osPriority_t) osPriorityNormal,
};
```

**Плюсы:**
- Простое решение
- Оставляет запас для будущих расширений
- Не требует изменения логики

**Минусы:**
- Увеличивает общее использование RAM на ~4 KB

#### Вариант 2: Вынести большие буферы в статическую память

В `http_server.c`:
```c
/* Статические буферы вместо локальных */
static char s_http_body_buf[4096];
static char s_http_rx_buf[768];
static char s_http_hdr_buf[256];

/* В функции обработки GET: */
char *body = s_http_body_buf;  // Вместо char body[4096];
```

**Плюсы:**
- Экономит стек
- Буферы переиспользуются

**Минусы:**
- Требует синхронизации (один запрос за раз)
- Увеличивает использование статической памяти

#### Вариант 3: Комбинированный подход

- Увеличить стек до 3072 * 4 = 12288 байт
- Вынести только самый большой буфер `body[4096]` в статическую память

**Результат**: стек будет использовать ~3500 байт вместо 7404, запас ~8700 байт.

## Рекомендации по оптимизации

### Приоритет 1: КРИТИЧНО - исправить httpTask

**Действие**: Увеличить стек httpTask до 3072 * 4 = 12288 байт

**Обоснование**: Текущее использование 90.3% критически опасно. При пиковых нагрузках возможен stack overflow.

### Приоритет 2: Оптимизация других задач

**Действие**: Уменьшить стеки задач с низким использованием:
- supervisorTask: 512 → 384 * 4
- rs485Task: 512 → 384 * 4
- watchdogTask: 512 → 384 * 4
- doorsTask: 512 → 384 * 4
- canTask: 512 → 384 * 4

**Экономия**: ~2560 байт

**Баланс**: 
- Увеличение httpTask: +4096 байт
- Уменьшение других задач: -2560 байт
- **Итого**: +1536 байт (приемлемо)

### Приоритет 3: Мониторинг

После изменений:
1. Перекомпилировать и прошить
2. Запустить `mem stat` несколько раз в разных режимах
3. Убедиться, что httpTask использует < 70%
4. Проверить работу при пиковых нагрузках (множественные HTTP запросы)
